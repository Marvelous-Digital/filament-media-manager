# Media Library — Design Spec

**Date:** 2026-07-16
**Package:** `marvelous-digital/filament-media-manager`
**Scope:** v1 — the media library page for uploading and managing raw media

## Vision (context beyond v1)

The plugin will ultimately provide a full media pipeline for Filament apps:
media is uploaded once as a high-fidelity original; content components later
pick media, define a focus point, override alt text, and get responsive size
variations generated (queued or live, per settings) using Laravel's
first-party image manipulation API (`Illuminate\Support\Facades\Image`,
Laravel 13.20+).

**v1 builds only the foundation:** a media library page to upload, organize
(nested folders), and manage raw media with editable name and alt text, plus
one auto-generated preview thumbnail. Originals are never used frontend.

## Decisions (from brainstorming)

- **Formats:** any file type is accepted; images are the focus (real
  thumbnails), video/documents/other get type icons for now.
- **Folders:** nested (filesystem-like), breadcrumb navigation.
- **Originals:** stored byte-for-byte, never re-encoded.
- **Thumbnail:** generated by a job, queued or sync per config.
- **UI:** fully custom Livewire media browser (Finder-style unified grid),
  not a standard Filament resource table.
- **Upload flow:** upload first with original filename, edit metadata after.
- **Naming:** vendor `marvelous-digital`, namespace
  `MarvelousDigital\FilamentMediaManager`.

## 1. Package setup

- Run skeleton `configure.php` for `marvelous-digital/filament-media-manager`.
- Dependencies: `filament/filament ^5.0`, `laravel/framework ^13.20`,
  `intervention/image ^4.0`.
- Plugin class registers the `MediaLibrary` page; service provider publishes
  config and migrations.

## 2. Data model

### `media_folders`

| column      | type                              |
| ----------- | --------------------------------- |
| `id`        | bigint pk                         |
| `name`      | string                            |
| `parent_id` | nullable fk → media_folders       |
| timestamps  |                                   |

Unique index on (`parent_id`, `name`). Relations: `parent`, `children`,
`media`.

### `media`

| column             | type                                                |
| ------------------ | --------------------------------------------------- |
| `id`               | bigint pk                                           |
| `folder_id`        | nullable fk → media_folders (null = root)           |
| `name`             | string — display name, editable                     |
| `file_name`        | string — original client filename                   |
| `disk`             | string                                              |
| `path`             | string — path of original on disk                   |
| `mime_type`        | string                                              |
| `type`             | enum: image / video / document / other (from mime)  |
| `size`             | unsigned bigint (bytes)                             |
| `width`, `height`  | nullable ints (images only)                         |
| `alt_text`         | nullable string                                     |
| `thumbnail_path`   | nullable string                                     |
| `thumbnail_status` | enum: pending / completed / failed / skipped        |
| `created_by`       | nullable user id                                    |
| timestamps         |                                                     |

### Storage layout

- Original: `{directory}/{ulid}/{filename}` on the configured disk,
  byte-for-byte as uploaded.
- Thumbnail: `{directory}/{ulid}/thumb.webp` next to it.
- Deleting a media row deletes its `{ulid}` directory.

The schema leaves room for a future `media_conversions` table and focus-point
columns without changes to these tables.

## 3. Media browser page

One Filament full-page Livewire component `MediaLibrary` ("Media" nav item)
with a custom Blade view.

- **Unified grid:** folder cards first, then media cards (image thumbnail, or
  type icon for video/document/other). "Load more" pagination. Empty state
  prompts to upload or create a folder.
- **Navigation:** clicking a folder enters it; the current folder id lives in
  the URL query string (links and back button work). Breadcrumbs back to root.
- **Toolbar:** search (scoped to current folder, matches name/alt text),
  New Folder, Upload.
- **Selection:** multi-select of items → bulk delete / bulk move.
- **Detail panel:** clicking a media item opens a slide-over with large
  preview, edit form (name, alt text, folder), file facts (size, dimensions,
  type, mime), and a download action.

All modals/forms (rename, new folder, move with folder-tree select, delete
confirmation, edit) are Filament Actions attached to the page — Filament
provides form/validation/modal machinery; only the grid is custom.

## 4. Upload pipeline

- Drag-and-drop anywhere on the grid + Upload button (hidden multi-file
  input). Files use Livewire native temporary uploads with a per-file
  progress list.
- On completion, an `UploadMedia` action class per file:
  1. Validate against configured allowed mime types and max file size.
  2. Store the untouched original.
  3. Create the `media` row in the current folder
     (`thumbnail_status = pending` for raster images, `skipped` otherwise).
  4. Dispatch `GenerateThumbnail`.
- **`GenerateThumbnail` job:**
  `Image::fromStorage($path, $disk)->orient()->scale(width: <config>)`
  `->toWebp()->quality(<config>)` → stored as `thumb.webp`; records original
  width/height on the row and sets `thumbnail_status`. Runs queued or sync per
  config. SVGs skip conversion and preview directly; non-images are skipped.

## 5. Configuration

`config/filament-media-manager.php`:

| key                   | default            |
| --------------------- | ------------------ |
| `disk`                | `public`           |
| `directory`           | `media`            |
| `accepted_mime_types` | broad default list |
| `max_file_size`       | 51200 (KB, = 50 MB) |
| `thumbnail.width`     | 600                |
| `thumbnail.format`    | `webp`             |
| `thumbnail.quality`   | 70                 |
| `thumbnail.queue`     | `true` (+ queue name) |
| `per_page`            | 30                 |

URL resolution: `Storage::url()` when the disk supports it, falling back to
`temporaryUrl()` for private disks.

## 6. Error handling

- Upload validation failures surface per-file in the progress list; other
  files in the batch continue.
- Thumbnail failures set `thumbnail_status = failed`; the card falls back to
  the type icon. A retry action regenerates.
- Deleting a folder requires it to be empty (v1); the delete action explains
  why when blocked.
- File deletion removes the row first-class and the directory best-effort
  (missing files never block row deletion).

## 7. Testing

Pest + Livewire tests on Orchestra Testbench (`Storage::fake`, `Queue::fake`):

- Upload persists file + row, sets correct `type`, dispatches job.
- Mime/size validation rejections.
- `GenerateThumbnail` produces the webp, records dimensions, sets status;
  skips SVG/non-images; failure path sets `failed`.
- Folder create / rename / delete (blocked when non-empty).
- Move, rename, alt-text edits; bulk delete / bulk move.
- Search scoped to current folder.
- Deleting media removes files from disk.

## Out of scope (v1)

Focus points, size variations/conversions, the picker form component for
other resources, video thumbnails, drag-to-move between folders, folder
permissions.
